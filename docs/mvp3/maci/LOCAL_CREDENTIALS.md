# Browser-local MACI credentials

The approved synthetic voter flow now creates a MACI v3 key pair in the browser after election approval and before public-key authorization. The MACI SDK's `Keypair` uses the existing Web Crypto browser adapter. IndexedDB stores the serialized private key under a versioned tuple of authenticated user ID, election ID, chain ID and MACI contract address. An atomic `add` prevents overwriting an existing local credential. Only public-key coordinates reach the authenticated authorization endpoint. Poll-join proofs, command signing and encrypted ballot creation remain in the browser; anonymous relay requests contain proof/calldata or ciphertext only.

The client reloads the local credential when the voter opens an election and compares its derived public key with the server's registered public key before joining or voting. If a registration exists and the key is absent or mismatched, voting stops. The client does not issue a replacement credential for that registration. Future recovery must prove ownership and replace or revoke the prior voting right atomically across the issuer and on-chain policy; account authentication alone is insufficient. No such replacement endpoint exists today.

The earlier encrypted backup envelope store remains in source for historical evidence, but the automatic flow cannot unlock those envelopes without their separate passphrases. Previously registered voters with only an old backup cannot use the new automatic flow on a fresh browser profile. They need a separately reviewed migration or recovery path; clearing storage does not grant another voting right. Browser storage can also be evicted or lost with the profile. There is no backend custody or automatic cross-device sync.

IndexedDB is persistence, not an XSS boundary. Any malicious same-origin script or compromised browser extension with page access can read the stored secret and potentially vote. The static export build hashes its own inline scripts and embeds a CSP meta policy with no `unsafe-inline` or `unsafe-eval` script allowance. It also emits `out/_headers` with the HTTP CSP, `frame-ancestors 'none'`, nosniff and no-referrer for compatible static hosts. A host that ignores `_headers` must configure those HTTP headers itself. The build-time public API and RPC origins must match deployed origins; serve the site over HTTPS outside localhost. CSP reduces injected-script execution but cannot protect against a compromised approved script, browser extension, device or origin.

No real-electorate key recovery, threshold custody or production security certification is claimed. The MACI proof artifact, dependency and BSC Testnet gates remain as recorded in `PROGRESS.md`.
