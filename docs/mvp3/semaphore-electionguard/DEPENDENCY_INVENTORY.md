## Advisory results

- Isolated `npm audit --omit=dev --json` exited 1 with **14 vulnerable package entries**: 9 high, 5 moderate, 0 critical. The graph includes `snarkjs@0.5.0` [double-spend advisory](https://github.com/advisories/GHSA-xp5g-jhg3-3rg2) via `circom_tester`, while actual `generateProof` imports `snarkjs@0.7.5`. `ws` advisory paths through ethers are installed; the probe used HTTP RPC, so WebSocket-specific paths were not exercised. `@zk-kit/artifacts` pulls compiler/testing utilities into a nominal runtime graph. These reachability findings are scoped to the executed script, not a production safety clearance.
- Isolated `pip-audit==2.10.1` against the Python freeze exited 1 and reported **two records for one Pydantic 1.9.0 advisory** ([GHSA-mr82-8j83-vxmv](https://github.com/advisories/GHSA-mr82-8j83-vxmv)); upstream pins Pydantic exactly at 1.9.0. The described input is a crafted email string; the synthetic probe does not process untrusted email, but application integration could. It cannot be silently upgraded without compatibility tests.

Production/browser/backend/cryptographic-worker package boundaries have **not** been finalized. The portable Python installation includes GUI/Mongo/test packages pulled by ElectionGuard's own runtime metadata even though the probe only uses cryptography and a helper. A minimal separately packaged worker would need its own exact lock, audit and terms review. The isolated npm package lock is tracked under research; the portable Python binary in ignored storage is not a product artifact.
