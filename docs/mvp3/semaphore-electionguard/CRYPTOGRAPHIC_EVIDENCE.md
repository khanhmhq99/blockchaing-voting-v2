The ElectionGuard [source verifier](https://github.com/Election-Tech-Initiative/electionguard-python/blob/1.4.0/src/electionguard_verify/verify.py) checks ballot validity, aggregation and direct decryption-share proofs. In the observed 2-of-3 compensated result, `share.proof` is `None` for a reconstructed share, causing `AttributeError` in `verify_decryption`. A focused 3-of-3 mutation incremented the published `PlaintextTallySelection.tally` by one while leaving its encrypted value and share proofs unchanged; `verify_decryption` still returned true. This source function does not by itself validate the announced final integer. The separate research verifier composes pinned upstream equations over public records and compares the complete recomputed result; its local 2-of-3 check passed. It still needs external review, broader record mutations and chain-backed archive completeness before a production verification claim.

The native key ceremony verified all partial backups and published the joint key; the probe did not export guardian private records. Guardian objects and ephemeral secret memory live in three child processes. IPC restricts method names; it returns public ceremony material and decryption shares, but the parent/host still commands all workers. The public ballot, manifest and context bytes are ignored research output; the tracked PoC reproduces them. The proof fetch path uses Semaphore circuit artifact version `4.13.0` as hardcoded in v4.14.4 `generate-proof.ts`; these artifacts worked with the v4.14.4 off-chain and Solidity vkeys, but ceremony provenance and production trust of downloaded artifacts remain unverified.

The focused probes cover positive paths and the named local negatives. An omitted ballot failed native aggregation verification and a changed election scope failed ballot verification. Six externally modified public record sets failed as described above. The changed final count was **accepted** by the limited source function. Added chain ballot and invalid candidate selection have not been executed end-to-end. See [security assumptions](SECURITY_ASSUMPTIONS.md) for exact coverage.
