# Application migration impact assessment

The working MACI v3 baseline has browser-side encrypted commands and join proofs, gasless sponsored calls, Supabase-backed eligibility and a coordinator with local verified processing/tally evidence ([MACI progress](../maci/PROGRESS.md)). The proposed stack changes the cryptographic protocol and trust model; no product code or schema was modified in this investigation.

| Area | Required change before migration | Evidence / unresolved issue |
| --- | --- | --- |
| Next.js Desktop voter UI | Generate/recover a Semaphore identity, obtain a frozen group root, encrypt an ElectionGuard ballot locally, bind the public bytes, generate proof, show receipt/inclusion status | Semaphore Node/browser package advertises browser export, but ElectionGuard Python is not a browser package. Core 2 mentions WASM, yet its selected tag says incomplete. Browser encryption packaging is NOT VERIFIED. Sending plaintext choice to NestJS would reduce ballot secrecy and is not approved. |
| NestJS auth and issuer | Keep username/password auth; issue one identity commitment per eligible account/election with atomic uniqueness, expiry/revocation and recovery policy | No issuer PoC yet. Database reader/issuer may correlate identity issuance with later metadata even without a stored nullifier join. |
| Gasless relayer | Accept only versioned public ballot/proof bytes, enforce size/rate/fee limits, submit the registry transaction and reconcile final receipts/reorgs | Local 452-byte calldata and 316k–333k gas observed. The relayer cannot itself be trusted to validate ElectionGuard ballots on-chain. |
| Supabase PostgreSQL | Version election manifest, group root, public ballot digest, archive pointer, accepted-chain index and verifier result; separate auth issuance from ballot/publication data | No migration designed or applied. A shared privileged DB role would undermine claimed unlinkability. |
| Guardian worker | Separate key ceremony, distinct process/storage, backup, partial-share production, absence compensation and audit publication | Three local processes with ephemeral key memory and restricted IPC passed the PoC. One parent/host controls all workers; no durable isolated custody or independent operator governance. |
| Election lifecycle | Freeze manifest/context/group root, open/close submissions, define invalid-ballot and replacement policy, publish accepted set and threshold tally | Research registry freezes parameters and closes locally. Direct contract submissions can commit invalid/unavailable ballots. |
| Public verification | Distribute exact canonical ballot bytes, manifest/context, accepted-chain order, guardian public records and complete 2-of-3 decryption evidence | Source verifier fails on compensated shares. A separate research CLI checks the local public record, three external record mutations and local chain snapshot; independent review, broader mutations and authenticated BSC accepted-set reconciliation remain. |
| Deployment/cost | Deploy official Semaphore components and separate protocol registry; confirm chain-97 proof execution and artifact storage | Four BSC creation estimates returned, but no chain-97 deployment/ballot execution. ElectionGuard on-chain verifier cost unknown. |

MACI's native encrypted-command processing/tally proof path would be replaced by separate ElectionGuard ballot validity, accepted-set aggregation and threshold-decryption evidence. The coordinator's ability to decrypt individual MACI commands could improve only with independently controlled ElectionGuard guardians and a working threshold publication path; the present one-host simulation does not establish that. MACI's vote-update semantics would be lost under the proposed one-ballot nullifier rule. Earlier MACI source, ABI, artifacts, records and benchmarks must remain reproducible if a future approved migration occurs.
