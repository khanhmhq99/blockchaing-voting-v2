# Accepted-set tally verification status

Status: local aggregation and aggregate decryption observed; **publicly verifiable aggregate decryption blocked**.

`research/mvp3/verify-bound-chain.mjs` accepted two synthetic ballots from different Semaphore identities on local Hardhat chain 31337. It fetched `BallotAccepted` logs and, for each, checked successful receipt, canonical block hash, transaction destination, `accept` calldata, nullifier, vote ID, message, manifest digest and all 64 ciphertext coordinates against the event. It rejected duplicate nullifiers and required exactly two records. It aggregated only the first two ciphertext fields with `circomlibjs` BabyJubJub point addition; decrypting the aggregate with the synthetic election private key gave counts `[1,1]`, summing to the accepted count 2. Internal checks rejected one omitted record, one duplicated added record, a substituted count and decryption with a wrong key. This is an observed internal check, not a public decryption proof.

## Required public evidence

For each active candidate field `j`, publish the accepted-set aggregate `(C1_j,C2_j)`, a decryption factor `D_j = sk * C1_j`, the bounded plaintext count `t_j`, and a proof of equality of discrete logarithms linking the election key `PK = sk * G` to `D_j = sk * C1_j`. A verifier must independently reconstruct the exact canonical accepted set and aggregate, validate point encodings and subgroup/nonidentity conditions, verify the proof under a domain covering chain ID, contract, manifest, key, candidate index, accepted-set commitment and aggregate, check `C2_j - D_j = t_j * G` for `0 <= t_j <= acceptedCount`, and check `sum(t_j) = acceptedCount`. Omission, addition, altered order/index, altered aggregate, key, count or proof must fail. A finalized block range and reorg replay policy are required.

The [DAVINCI DKG project](https://github.com/vocdoni/davinci-dkg) has BabyJubJub partial-decryption and DLEQ machinery, but its documented statements bind threshold share commitments and a DKG application key. Its license is AGPL-3.0. It has not been shown equivalent to this single-holder key and per-candidate aggregate format, and was not used as an unreviewed drop-in. No compatible reviewed implementation, domain transcript or negative-vector verification has yet passed. This blocks public tally correctness and the full MVP 3 feasibility gate. Do not report the `[1,1]` local result as independently verified.

The exact next crypto implementation step is to adapt a reviewed BabyJubJub Chaum–Pedersen/DLEQ prover and verifier to this single-holder statement, freeze its transcript encoding, and run the accepted-set mutation vectors before any deployment. If adaptation changes assumptions, record a versioned ADR before integration.
