## Implemented workflow

- Admin creates a MACI election from title, two to 125 unique candidates, start and end date/time. The browser displays its timezone. The API validates the fields, stores a durable idempotent job, runs the existing pinned local deployment and candidate-anchor scripts server-side, checks receipts, code hashes, chain bindings and timing, then persists the election. The UI polls job stages and exposes public addresses/transactions in Advanced Details.
- Voter requests participation without a wallet, sees `PENDING`/`APPROVED`/`REJECTED`, and can use the existing client-held MACI credential, encrypted backup, sponsored on-chain registration, joining proof and encrypted command flow after approval. The admin approves/rejects pending requests. A unique election/voter constraint and serializable review transaction prevent duplicate or conflicting decisions. Rejected accounts do not receive MACI authorization. Approval remains distinct from confirmed on-chain registration.
- Verified chain time drives `REGISTRATION` → `OPEN` → `CLOSED`; only accepted audit evidence drives `VERIFIED`. The registration/approval cutoff is before poll start. The monitor refreshes every 15 seconds and distinguishes account requests, eligibility, registered credentials, confirmed join/message projections, on-chain processing/tally batch counters, deployment health and application verification. Invalid historic deployments return unavailable current-chain join/message counts.
- The coordinator, public audit publisher and independent CLI verifier remain explicit. The publisher automatically attaches the pre-election canonical candidate configuration for a self-service job after the four-file evidence passes. `scripts/prepare-maci-coordinator-config.mjs` derives public coordinator inputs from a deployment file; the coordinator secret remains separate.

## Run the enhanced local application

These steps assume the ignored, pinned MACI v3 runtime/circuit artifacts and Node 24/npm 11 described in [MVP 3 MACI progress](../../mvp3/maci/PROGRESS.md) are already present. Run commands from the repository root on Windows using `npm.cmd` and the repository-local Node on `PATH` when the system Node differs. Do not reuse historic 31337 addresses after restarting Hardhat.

1. Point `DATABASE_URL` and `DATABASE_CA_PATH` at an **isolated local PostgreSQL fixture** with verified TLS and a synthetic admin account. Before mutation, confirm database name/host/port/TLS. Apply the existing baseline migrations if the fixture is new, then `202610240001_election_self_service` and `202610240002_local_chain_instances` in order through the approved local migration connection. The observed fixture used `psql -X -v ON_ERROR_STOP=1 -1 -f <migration.sql>`; it never contacted Supabase. Run `npm.cmd run prisma:validate` and `npm.cmd run build`.
2. Start a fresh persistent Hardhat chain: `npm.cmd run chain` (default `127.0.0.1:8545`). In a separate terminal with the local database environment set, start the API using the synthetic local key helper: `node scripts/maci-local-env.mjs -- node dist/services/api/src/main.js`. Keep the chain and API running. The helper refuses nonlocal chain IDs and keeps the coordinator key in ignored storage.
3. In another terminal, set `NEXT_PUBLIC_API_URL=http://localhost:3001` and `NEXT_PUBLIC_MACI_RPC_URL=http://127.0.0.1:8545`, then run `npm.cmd run dev:web`. Login as the existing synthetic admin, open `/admin/maci`, enter title, candidates and start/end times at least ten minutes ahead of both server and chain time, and wait for `READY`. A longer lead time is prudent for proof work. Voters create synthetic accounts, request participation, wait for admin review, then perform the existing encrypted-backup and MACI journey.
4. After the poll closes on chain, the coordinator remains an explicit advanced operation. Derive its public input without retyping addresses: `node scripts/prepare-maci-coordinator-config.mjs research/mvp3/maci/probe-output/deployments/<jobId>/deployment.json`. Run `node scripts/maci-local-env.mjs -- node scripts/maci-coordinator.mjs research/mvp3/maci/probe-output/deployments/<jobId>/coordinator-config.json`. Submit its four original public evidence files through Advanced Operations. The API validates and publishes the canonical candidate configuration for this self-service job. Run `npm.cmd run verify:election -- --evidence <public-dir> --rpc http://127.0.0.1:8545 --config <configuration.json> --config-sha256 <prior-pinned-hash> --confirmations 1` independently. The caller must obtain and retain the candidate configuration hash before the election; a later API response alone is not an independent prior pin.
